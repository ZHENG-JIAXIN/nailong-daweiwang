# 输入系统 UX 规格 · 双浮动摇杆（方案 A · v2.0）

> 阶段：Phase 6 打磨期 / 手感调整
> 版本：v2.0 · 2026-11-10（取代 v1.0 固定 D-pad 版）
> 适用：Godot 4.7 Web 导出，竖屏 720×1280（portrait）

## 1. 从 v1.0 改到 v2.0 的原因

v1.0 用「左下角固定 W/A/S/D + 右半屏绝对触摸点瞄准」，实测反馈三个问题：

1. **按键太小**：76×76 逻辑像素，手机上按不准、不过瘾
2. **位置固定**：锚死左下角，手够不着、姿势受限
3. **射击角度不足 360°**：瞄准是 `aim_dir = 触摸点 − 角色位置`，而触摸点被
   限制在右 55% 屏宽内。手指永远到不了角色左侧，朝左的锥形极窄；角色跑到
   屏幕右边时角度还会乱跳

根因是把**绝对坐标**当方向用。v2.0 改为：方向 = **手指相对按下点的偏移向量**，
与角色位置、手指落在屏幕哪里都无关，因此全向可达，且摇杆跟着手指出现。

## 2. 输入映射表

| 动作 | PC | 移动端 |
|---|---|---|
| 移动 | `WASD` / 方向键 | **左半屏任意处按住** → 就地生成左摇杆，拖动偏移决定方向与速度 |
| 瞄准 | 鼠标位置 | **右半屏任意处按住** → 就地生成右摇杆，拖动偏移决定 360° 朝向 |
| 开火 | 鼠标左键按住 | 右摇杆按住期间持续开火 |
| 切武器 | `1`–`4` | 暂不提供屏幕键（见 §6） |
| 换弹 | `R` | 同上 |

**PC 端不显示摇杆**（无触摸事件），保持键鼠；摇杆层只在 `state == "playing"`
且出现触摸时可见。

## 3. 摇杆规格

| 参数 | 值 | 说明 |
|---|---|---|
| 底盘半径 | `104 px` | 直径 208px，约为 v1.0 按键面积的 20 倍 |
| 摇杆头半径 | `44 px` | 直径 88px，指腹命中舒适 |
| 死区 | `8 px` | 低于此偏移不产生方向，防手抖 |
| 最大偏移 | `104 px` | 超出则钳制在底盘边缘 |
| 分区 | 屏宽 50% | 左半屏→左摇杆，右半屏→右摇杆 |
| 浮动基准 | 按下点 | 摇杆在手指按下位置就地生成，松开即消失 |

- 视觉：左摇杆青蓝、右摇杆橙，均为半透明圆盘 + 描边 + 实心摇杆头，代码绘制
- 按下淡入、松开淡出，不常驻遮挡视野
- 绘制层 `mouse_filter = IGNORE`，不吞掉登录/菜单按钮的点击

**移动模型**：`pad_dir = 偏移 / 底盘半径`（长度 0..1）→ 轻推慢走、推到底全速，
全向连续，不再只有 8 向。`mv = 键盘向量 + pad_dir`，`|mv| > 1` 时归一化。

**瞄准模型**：`aim_dir = 右摇杆偏移.normalized()`，直接赋给角色朝向，
**不参与任何坐标减法**，因此正上/正下/正左/正右及任意角度都能瞄到。
松开摇杆保留最后一帧朝向，停火但不再乱转。

## 4. 双指追踪（关键实现）

用 `InputEventScreenTouch.index` / `InputEventScreenDrag.index` 追踪手指：

- 每侧只认第一根落在该半屏的手指，记为 `left_idx` / `right_idx`
- 已归属的手指后续只更新 `current`，不重新分区
- 松手按 `index` 精确释放对应侧，另一侧不受影响
- **双指先后顺序任意**：先按右侧开火再按左侧移动，或反过来，都正常
- 不再依赖 Godot 的「触摸转鼠标」（该机制只跟随第一根手指），
  v1.0 遗留的多点触控隐患一并解除
- `touch_seen` 一经置位即忽略所有 `InputEventMouseButton`，避免触摸模拟的
  鼠标事件造成「按左摇杆误开火」或开火状态残留

## 5. 交互状态与边界

| 场景 | 期望行为 |
|---|---|
| 左摇杆推到底 | 全速移动；轻推则按比例降速 |
| 左摇杆 + 鼠标（PC 混合设备） | 两者向量叠加并归一化，不超速 |
| 右摇杆绕圈拖动 | 朝向连续 360° 跟随，子弹朝摇杆方向 |
| 右摇杆按下不拖动 | 保持当前朝向持续开火 |
| 松开右摇杆 | 立即停火，朝向保留 |
| 松开左摇杆 | 立即停止移动，不残留 `pad_dir` |
| 双指任意先后顺序 | 两侧互不干扰 |
| 切到结算 / 返回菜单 | 两侧索引、方向、开火全部复位，摇杆层隐藏 |
| 登录页 / 主菜单 | 不显示摇杆 |

## 6. 已知取舍（本次不做）

- 移动端暂不提供「切武器 / 换弹」屏幕键：远程空仓自动换弹、近战无弹药；
  若 Playtest 显示切枪需求强烈，再补右侧按钮组
- 不做固定位置摇杆：用户明确要求跟随手指
- 不做惯性缓动 / 死区可视化刻度，保持轻量
- 不改变角色朝向绘制逻辑，武器仍按 `aim_dir` 绘制
- PC 端不提供鼠标拖动摇杆（如需可另加，会让键鼠玩家也能试手感）

## 7. 验收标准

1. PC：仅按 WASD 能移动，鼠标只改变朝向、不带动位置
2. PC：按住左键后退（S + 反向鼠标）能持续开火
3. 移动端：左半屏任意处按住出现大摇杆，推动能全向移动、轻推慢走
4. 移动端：右摇杆绕一圈能把武器/子弹打到 **360° 任意方向**，无死角、不跳角
5. 移动端：先按右侧开火再按左侧移动，两步都生效
6. 菜单 / 登录 / 结算不出现摇杆，不残留移动或开火
7. 双端 Web 导出后行为一致，手机虚拟键盘仍可输入用户名

## 8. 部署约束

改 `.gd` 后必须重新导出 Web 并提交 `index.pck` + `index.html` 再 push，
否则 Godot 里能玩、线上仍是旧版。导出预设已开启
`html/experimental_virtual_keyboard`，重导会自动带上 `experimentalVK:true`，
**无需手动改**。`index.wasm.gz` 由 Netlify build command 自动重生成，
无需手动同步。新增的 `src/joystick_overlay.gd` 会随导出一并打进 pck。
