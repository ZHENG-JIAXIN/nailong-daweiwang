# 关卡进度规格 · 无尽关卡制（方案 A）

> 阶段：Phase 5 制作期 / 玩法扩展
> 版本：v1.0 · 2026-11-11
> 适用：Godot 4.7 Web 导出，竖屏 720×1280

## 1. 问题与目标

旧版 `LEVELS` 只有 3 关，目标为**累计分数** 300 / 800 / 1600。
`check_progress()` 达标就换背景 + 横幅，第 3 关达标直接 `game_win()` 结束。
玩家反馈「达到值了然后就成功了没有了，缺少可玩性」——
本质是**没有持续目标、没有单关成就反馈、难度曲线在 3 关就截断**。

目标（自我决定论）：用「胜任感 + 清晰短目标 + 递增挑战」替代一次性终点，
让每一关都有「开始 → 达成 → 结算 → 主动继续」的完整循环。

## 2. 核心模型

| 概念 | 定义 |
|---|---|
| `level_index` | 第几关，从 1 开始，**无上限** |
| `current_level` | 主题索引 = `(level_index - 1) % LEVELS.size()`，三主题循环复用 |
| `score` | 累计总分，用于最高分 / BOSS 阈值 / 最终结算 |
| `level_score` | **本关得分**，每关重置，用于过关判定 |
| `level_kills` | 本关击杀数，每关重置，用于结算展示 |
| `level_target` | 本关目标，`300 + 200 × (level_index - 1)` |
| `state` | 新增 `levelclear`（过关结算），与 `playing` / `gameover` / `menu` / `login` 并列 |

**得分双记**：所有加分点（吞噬小鱼、击杀普通鱼、击杀 BOSS）同时累加
`score` 与 `level_score`；击杀同时累加 `kill_count` 与 `level_kills`。

## 3. 难度曲线（每关递增，带上限防失控）

| 项 | 公式 | 上限 |
|---|---|---|
| 过关目标 | `300 + 200 × (n-1)` | 无（无尽） |
| 鱼体型/速度倍率 `lvl_scale` | `1 + 0.08 × (n-1)` | `2.8` |
| 捕食者概率 `pred_chance` | `基础 + 0.04 × (n-1)` | `0.82` |
| 生成间隔 | `基础 - 0.01 × (n-1)` | `0.22s` |
| 过关奖励币 | `10 + 5 × (n-1)` | 无 |

设计意图：前 3 关与旧版体感接近，第 4 关起明显加压；封顶避免高关数
变成不可玩的弹幕。心流平衡上让「熟练度增长」与「压力增长」同步。

## 4. 过关结算面板

达标时进入 `state = "levelclear"`：停止生成、清空场上鱼与 BOSS、隐藏摇杆与
武器栏，弹出居中面板（半透明遮罩 + VBox）：

- 标题：`第 N 关 完成`
- 统计：`本关得分 / 目标`、`本关击杀`、`累计总分`
- 评价：按剩余生命与超额程度给 `S / A / B`
  - `S`：HP ≥ 80% **且** 本关得分 ≥ 目标 × 1.2
  - `A`：HP ≥ 50% **或** 本关得分 ≥ 目标 × 1.2
  - `B`：其余
- 奖励：`+X 奶龙币`（写入存档）
- 按钮：`继续第 N+1 关 →`（唯一前进入口，玩家主动掌舵）

面板 `mouse_filter = STOP`，避免触摸穿透到游戏层。

## 5. 继续下一关 `next_level()`

1. `level_index += 1`，重算主题索引与背景色
2. `level_score = 0`、`level_kills = 0`、重算 `level_target`
3. 清空场上鱼、重新铺 16 条
4. 重置 BOSS 阈值（`score + 600` / `kill_count + 15`），保证每关都有机会出 BOSS
5. **每 3 关开场强制生成 BOSS**（第 3、6、9… 关），形成阶段高潮
6. `state = "playing"`，恢复摇杆 / 武器栏 / 生成计时器，显示关卡横幅

## 6. 结束条件

**死亡才最终结算**：`game_over()` 文案改为
`游戏结束 / 到达第 N 关 / 总分 / 最高分`，`GameManager.record_score(score)` 照旧。
无尽模式**不调用 `game_win()`**（保留函数但不再接线），不存在「通关」终点。

## 7. 移动端武器快捷栏（联动需求）

HUD 下方增加 4 个短名按钮（`M4A1 / 巴雷特 / 军刀 / 战斧`），当前武器高亮，
点击即 `switch_weapon(i)`；PC 的 `1-4` 键保留。

**冲突规避**：双浮动摇杆会在「任意触摸落点」生成。实现时需在
`_handle_touch()` 里判断落点是否命中 `weapon_bar.get_global_rect()`，
命中则直接返回（不生成摇杆），由按钮自己接收触摸。
按钮区只在 `playing` 可见，结算 / 菜单 / 登录隐藏。

## 8. 验收标准

1. 第 1 关目标 300，达标后弹出结算面板（不是直接成功/结束）
2. 结算面板显示本关得分、击杀、评价、奖励币；点「继续」进第 2 关
3. 第 2 关目标 500、背景换主题、鱼更凶；本关得分从 0 重新计
4. 第 3 / 6 / 9 关开场出现 BOSS
5. 连续玩到 10 关不崩、无内存泄漏（鱼与 BOSS 每关清理）
6. 死亡结算显示「到达第 N 关」与总分，最高分正常写入
7. 移动端：点武器按钮能切枪且**不会同时生成摇杆**；PC `1-4` 仍有效
8. 结算期间不会继续掉血 / 生成鱼 / 触发开火

## 9. 已知取舍

- 不做关卡选择界面与解锁存档（那是方案 B），关卡进度仅本局有效
- 不做限时目标 / 多目标组合（避免同时改太多系统）
- 三主题循环复用，不新增美术资源
- 目标分数与难度公式为初版数值，Playtest 后再微调
