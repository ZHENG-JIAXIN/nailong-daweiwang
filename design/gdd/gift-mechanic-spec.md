# 地图随机礼包机制规格

> 阶段：Phase 5 制作期 / 玩法扩展
> 版本：v1.2 · 2026-11-11（间隔最终定为 20s；礼包放大并提到上层）
> 适用：Godot 4.7 Web 导出，竖屏 720×1280，单线程

## 1. 需求原文与落地假设

用户要求：每 1 分 30 秒在地图随机位置生成 1 个可拾取礼包，礼包仅存在 8 秒，
超时自动消失；玩家拾取并打开后移除礼包，并**仅随机触发一种效果**；
效果按增益:减益 = 9:1 决定，再从对应列表随机选一种；
所有效果（含无敌金身）持续时间上限 10 秒，到期自动失效并恢复原有状态。

**v1.1 修订（用户反馈）**：生成间隔由 90 秒改为 30 秒；
同时放大礼包并提升绘制层级，解决「游戏中看不到礼包」的问题。
诊断出三处叠加原因，见 §9。
**v1.2 修订（用户反馈）**：生成间隔进一步定为 **20 秒**（当前生效值）。

为消除歧义，以下为实现时采用的具体假设（如需调整请指出）：

| 歧义点 | 采用值 |
|---|---|
| 「拾取并打开」 | **碰到即自动打开并移除**，不额外要求按键/点击 |
| 减益「累计最多扣除一半血量」 | 上限 = **拾取瞬间当前 HP 的 50%**，10 秒内匀速扣完，因此不会致死 |
| 减益「立即扣除 20% 血量」 | **最大生命 × 20%** |
| 「持续期间降低武器伤害」 | 所有武器伤害 **× 0.5** |
| 增益「15% 吸血」 | 每次实际造成伤害后回复 `伤害 × 15%`，上限不超过 max_hp |
| 增益「子弹变大」 | 视觉半径与碰撞半径 **× 1.8**（不改伤害），近战不受影响 |
| 增益「无敌金身」 | `take_damage()` 直接返回，完全免伤 |
| 计时器起点 | **每关重置** 20 秒；结算、换关、死亡时停止生成并清场 |
| 同时存在数量 | 最多 1 个（20s 间隔仍远大于 8s 寿命，不会叠出第二个） |

## 2. 生成与消失

| 参数 | 值 |
|---|---|
| 生成间隔 | `20.0s`（每关重置，v1.2 由 30s 下调） |
| 存在时长 | `8.0s`，超时 `queue_free()` |
| 位置 | 地图内随机，X 距边缘 ≥ 80px、Y 范围 290~1120（避开顶部 HUD、武器快捷栏与底部摇杆），与玩家距离 > 140px |
| 视觉 | 代码绘制金色礼盒（52×52）+ 红色十字丝带 + 蝴蝶结 + 直径 72 的金色光环；`modulate` 脉冲闪烁，剩余 2 秒加快；`z_index = 2` 画在 HUD/横幅之上 |
| 性能 | 闪烁只改 `modulate`（不重绘）；`_draw()` 仅创建时一次 |

礼包挂在 `fish_layer` 下并加入 `gift` 组 —— 现有所有清场循环
（`level_clear` / `next_level` / `start_game` / `_clear_battlefield`）天然覆盖它。

## 3. 效果抽取

```
p = randf()
if p < 0.9: 从增益表 3 选 1
else:       从减益表 2 选 1
```

- **增益**（各 30% 条件概率 / 总体各 30%）：`lifesteal`、`big_bullet`、`invincible`
- **减益**（各 50% 条件概率 / 总体各 5%）：`dot`、`explosion`

每次**只触发一种**，拾取新效果前先 `clear_gift_effect()` 恢复原状态，
因此不会出现叠加或残留系数。

## 4. 效果表

| ID | 类型 | 效果 | 持续 | 实现位置 |
|---|---|---|---|---|
| `lifesteal` | 增益 | 回血 = 造成伤害 × 15% | 10s | `player.on_dealt_damage()`，由 `bullet` 命中与近战 `swing()` 回调 |
| `big_bullet` | 增益 | 子弹视觉 + 碰撞半径 × 1.8 | 10s | `player.fire_bullet()` 传倍率给 `bullet.setup()` |
| `invincible` | 增益 | 完全免伤 | 10s | `player.take_damage()` 开头直接返回 |
| `dot` | 减益 | 10s 内匀速扣血，累计 ≤ 拾取时 HP 的一半 | 10s | `player._process()` 里 `_tick_gift_dot()` |
| `explosion` | 减益 | 立即扣 `max_hp × 20%`；期间武器伤害 × 0.5 | 10s | `apply_gift_effect()` 立即结算 + `fire_bullet/swing` 乘系数 |

**恢复原状态**：所有效果都是标志位或乘性系数，`clear_gift_effect()` 把
`gift_effect / gift_timer / bullet_scale / damage_mult / dot_*` 全部复位即可，
不改动任何基础数值（伤害、速度、半径、HP 上限均不受影响）。

## 5. 状态与 UI

- `player.gift_effect` / `gift_timer`（剩余秒数）
- HUD 底部独立 Label（不进顶部 VBox，避免与武器快捷栏重叠）显示
  `礼包: <名称>  <剩余秒数>s`；无效果时为空
- 生成礼包时显示 1.6s 横幅「限时礼包出现！（8 秒）」；拾取时显示
  「礼包：<效果名>（10 秒）」，并播放轻量 `play_eat()` 音效

## 6. 清理矩阵

| 时机 | 礼包实体 | 玩家效果 |
|---|---|---|
| 8 秒超时 | 自动消失 | 无 |
| 玩家拾取 | 立即移除 | 应用新效果（先清旧） |
| 10 秒到期 | — | 自动 `clear_gift_effect()` |
| 过关结算 `level_clear()` | 清场移除 | `clear_gift_effect()` |
| 进入下一关 `next_level()` | 清场移除、计时器重置 | 保持清空 |
| 死亡 `game_over()` | `_clear_battlefield()` 移除 | 随 player 释放 |
| 返回菜单 / 退出登录 | 同上 | 同上 |

## 7. 验收标准

1. 开局后第 20 秒出现第一个礼包，之后每 20 秒一个；每关重新计时
2. 礼包 8 秒未被拾取自动消失，场上不残留
3. 碰到礼包立即消失、只触发一种效果，HUD 显示名称与倒计时
4. 大量抽样下增益:减益 ≈ 9:1；增益 3 种、减益 2 种都能抽到
5. 15% 吸血、子弹变大、无敌金身各自生效且 10 秒后完全恢复
6. 持续扣血 10 秒累计不超过拾取时 HP 的一半，不致死
7. 爆炸立即扣 20% 最大生命，期间武器伤害减半，10 秒后恢复
8. 结算 / 换关 / 死亡后没有残留礼包与残留效果
9. 弹幕与礼包同屏时帧率无明显下降（无每帧重绘）

## 8. 已知取舍

- 礼包不做开启动画 / 二次确认，保持「碰到即开」的轻量手感
- 不做效果叠加、不做稀有度、不做礼包币奖励（避免动经济系统）
- 不在结算暂停期间推进生成计时与效果计时（`_process` 仅在 `playing` 调度）

## 9. 「看不到礼包」排障（v1.1）

用户反馈礼包在游戏中看不到。诊断出三处叠加原因：

1. **主因：版本没上线**。最近提交仍是 BOSS 版 `303eb9d`，礼包相关文件
   （`gift.gd`、`main.gd` 的调度与抽取）全部还在工作区未提交；
   本地 `index.pck` 与线上同为 `8609916`，时间戳 17:00 早于礼包代码 17:14。
   → 线上根本没有礼包逻辑，等多久都不会出现。**必须重新导出 Web + push**。
2. **90 秒间隔太长**，即使版本上线，短局内也可能等不到第一个。
   → 先改 30 秒，v1.2 再下调到 20 秒。
3. **视觉不显眼**：原礼盒仅 34×34 px，且 `z_index = 0` 与 HUD 同层，
   会被 1.6 秒的横幅半透明黑底压暗、可能被顶部武器快捷栏遮住。
   → 放大到 52×52 + 金色光环、`z_index = 2`、生成 Y 下限提到 290 避开按钮区。

修复后验收：部署新包后，开局 20 秒应能明显看到带光环的礼盒，
8 秒未拾取自动消失，碰到立即开。
