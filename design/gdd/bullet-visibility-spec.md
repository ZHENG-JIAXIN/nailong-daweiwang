# 子弹可见性规格 · 背景自适应对比

> 阶段：Phase 6 打磨期 / 可访问性
> 版本：v1.0 · 2026-11-11
> 适用：Godot 4.7 Web 导出，竖屏 720×1280

## 1. 问题

`bullet.gd` 旧绘制：淡黄拖尾 `Color(1.0,0.95,0.45,0.5)` + 金黄圆
`Color(1.0,0.9,0.3)` + 白芯，半径仅 4.5px。

三关背景亮度差异极大：

| 主题 | 背景色 | 相对亮度 | 旧子弹观感 |
|---|---|---|---|
| 浅海乐园 | `0.74, 0.91, 1.0` | ~0.89（浅） | 白芯/淡黄拖尾几乎糊进背景 |
| 珊瑚浅滩 | `1.0, 0.86, 0.80` | ~0.88（浅） | 同上，对比不足 |
| 深渊秘境 | `0.12, 0.22, 0.42` | ~0.21（深） | 反而清晰 |

玩家反馈「子弹要跟背景区别开来」。这是可访问性问题（低对比度、
小目标、快速移动），不是美术风格问题。

## 2. 判据

用感知亮度公式判断当前背景：

```
lum = 0.299·R + 0.587·G + 0.114·B
浅背景 := lum > 0.62
```

该标志由 `main.gd` 在每次切换背景时写入 autoload 单例
`GameManager.bg_is_light`（运行时字段，**不进存档**），
`bullet.gd._draw()` 直接读取——Godot 中 autoload 是全局标识符，零额外耦合。

## 3. 配色规格

| 元素 | 浅背景（lum > 0.62） | 深背景 |
|---|---|---|
| 描边外环（R=6.5） | `0.06, 0.09, 0.18` 近黑 | `1.0, 1.0, 1.0, 0.95` 亮白 |
| 亮芯（R=4.6） | `1.0, 0.55, 0.10` 亮橙 | `1.0, 0.85, 0.25` 金黄 |
| 中心点（R=2.0） | 白 | 白 |
| 拖尾（长 18，宽 5） | `0.15, 0.12, 0.30, 0.65` 深紫 | `1.0, 0.90, 0.55, 0.55` 亮黄 |
| 碰撞半径 | `6.0` | 同 |

**设计原则**：双层结构保证任意背景都有对比——浅背景靠深色描边勾勒轮廓，
深背景靠亮描边 + 亮芯发光。中心白点在两种模式下都保留，作为瞄准参考点。

## 4. 尺寸与动效

- 视觉半径 `4.5 → 6.5`（+44%），碰撞半径 `5 → 6` 与视觉对齐
- 拖尾长度 `12 → 18`，宽度 `3 → 5`，提升高速移动时的可追踪性
- 不做粒子 / 发光 shader（单线程 Web 导出，避免额外绘制开销）
- 不做每帧 `queue_redraw()`：`_draw()` 只在 `setup()` 后画一次，
  子弹本体靠 `global_position` 移动，沿用现有零重绘策略

## 5. 与关卡制的联动

无尽关卡制下三主题循环复用，背景会在每关切换。因此：

- `main.gd` 必须**在每次换背景时**（开局 + `next_level()`）同步更新
  `GameManager.bg_is_light`，否则第 4 关回到浅海主题时会沿用上一关的深色配色
- 已在场上的子弹不重绘（寿命 ≤ 2.2s），换关时会被清空，不会残留错误配色

## 6. 验收标准

1. 浅海乐园 / 珊瑚浅滩：子弹有明显深色轮廓，快速移动时眼睛能跟上
2. 深渊秘境：子弹亮白描边 + 金黄芯，不糊在深蓝里
3. 第 3 → 4 关（深 → 浅主题循环）配色正确切换，没有沿用旧关颜色
4. 命中判定与视觉大小一致，不出现「看得见打不到」
5. Web 单线程导出下帧率无明显下降
