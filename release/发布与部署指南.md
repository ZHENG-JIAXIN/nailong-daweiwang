# 发布与部署完整教程（非商用 · 同人作品）

> 目标：把《奶龙大胃王》（Godot 4.7 项目，位于 `src/`）从「源码」导出为可运行包，并部署到公网供他人游玩。  
> **合规前提**：使用 IP 角色仅限**非商用**；正式商用前须取得授权。当前角色贴图为原创占位图，可随时替换为已授权/自制素材。

---

## 0. 前置说明

- 本游戏是多用户网页/移动游戏：登录/注册、角色切换、吞噬成长、3 难度/3 关卡、程序化音频、最高分。
- 存档位置：`user://users/<用户名>/save.json`。**Web 导出后该路径落在浏览器 IndexedDB**，按浏览器/设备隔离，符合「多用户各自独立」的预期。
- 本教程覆盖 **Web（浏览器，最易分享）**、**Android**、**iOS** 三条线，以及多种免费托管方式。

---

## 1. 准备工作

1. 安装 **Godot 4.7（标准版，免费 MIT）**：官网 godotengine.org 下载，双击即开，无需安装。
2. 下载**导出模板**（仅首次需联网）：
   - 顶部菜单 `编辑器 → 管理导出模板 → 下载`（或 `Editor → Manage Export Templates`）。
3. 准备本仓库 `src/` 作为项目根（已含 `project.godot`、`Main.tscn`、`game_manager.gd` 等）。
4. 确认角色贴图已就位：`src/assets/characters/0.png`(奶龙/黄)、`1.png`(噜噜/绿)、`2.png`(奶娃/粉)。
5. `project.godot` 已预置 Web 导出预设 `[preset.0]`；若缺失，按 §2.1 手动添加。

---

## 2. Web 导出（浏览器即玩，最易分享）

### 2.1 配置导出预设

1. `项目 → 导出`（Project → Export）→ 点 `添加`（Add）→ 选 **Web** → 命名 `Web`。
2. 关键选项（导出面板）：
   - **导出路径（Export Path）**：选一个空文件夹，例如 `release/web/index.html`。
   - **可运行（Runnable）**：勾选。
   - **导出为单一文件（Export to a single file / .html 内含 .pck）**：勾选后只产出一个 `index.html`，分享最方便（也可取消，得到分离的 `.wasm` + `.pck`，加载更快）。
   - **线程（Threads）**：**必须为 Off**。已在 `project.godot` 的 `[preset.0.options]` 锁定 `variant/thread_support=false`（Godot 4.3+ 默认也是 Off）。关掉可避免浏览器要求 `COOP/COEP` 响应头，任意静态托管都能直接跑；**GitHub Pages 不支持自定义头，所以这条是硬要求**。
  - **扩展支持（Extensions Support）**：保持 Off（本项目无 GDExtension）。
  - **VRAM 纹理压缩**：`for_mobile=true` 已开，提升手机浏览器兼容性（代价是包体略大，介意可关）。
   - **嵌入游戏数据到 .html**：若选单一文件，勾选即可。
3. 预设已就绪（`project.godot` 含 `[preset.0]`），关键值：
   ```
   [preset.0]
   name="Web"
   platform="Web"
   runnable=true
   export_filter="all_resources"
   export_path="release/web/index.html"

   [preset.0.options]
   variant/thread_support=false             ; 单线程，关掉 Thread Support
   vram_texture_compression/for_mobile=true  ; 手机浏览器纹理兼容
   ```
   > 工程根是 `src/`（`project.godot` 在此）。`export_path` 用工程内相对路径 `release/web/`，即 `src/release/web/`，导出后构建文件与 `_headers`/`.nojekyll` 集中一处，方便整体部署。

### 2.2 执行导出

- 打开 Godot → `项目 → 导出` → 选中 `Web` 预设 → 点 `导出项目`（Export Project）。
- 目标文件夹已预填 `release/web/`（`src/` 工程根内的 `src/release/web/`）。**务必导出到这个目录**——里面已放好部署所需的 `_headers`（Netlify 用）和 `.nojekyll`（GitHub Pages 用），会随构建一起被带走。
- 等待进度条完成。产物：`release/web/index.html` + 同目录 `index.wasm`、`index.pck`、`index.js`、`index.png`、`index.icon.png` 等。
- ⚠️ 不要双击 `index.html` 打开（浏览器禁止 `file://` 跑 WebGL/音频），必须走本地 HTTP 或上传托管。

### 2.3 本地预览（必须，不能双击打开）

浏览器禁止 `file://` 直接跑 WebGL/音频，需起一个本地 HTTP 服务：

- 有 Python：`cd release/web && python -m http.server 8000`
- 有 Node：`npx serve release/web`
- 浏览器访问 `http://localhost:8000`，逐项验证：登录/注册、角色切换、吞噬成长、音效、关卡进阶、结算与最高分。

## 3. 部署到公网（任选其一）

### 3.1 GitHub Pages（免费，推荐）

> GitHub Pages **不支持自定义响应头**，所以「Thread Support = OFF」是硬要求（已锁定，见 §2.1）。同时务必带上 `.nojekyll`，否则 Jekyll 可能误处理文件导致 404。

1. 把 `src/release/web/` 全部内容（含 `index.html`、`.wasm`、`.pck`、`.js`、`.png`、`_headers`、`.nojekyll`）推到 GitHub 仓库（例如 `yourname/nailong-game`）。
2. 仓库 `Settings → Pages`：Source 选分支 + 目录（根目录或 `/docs`）。最省事：把 web 产物放到仓库根或 `/docs`，Pages 源指向该目录。
3. 获得 `https://yourname.github.io/nailong-game/`。首次部署约 1–2 分钟生效。

### 3.2 Netlify / Vercel / Cloudflare Pages（免费额度，自动 HTTPS）

- **Netlify Drop**：打开 app.netlify.com/drop，把 `release/web` 文件夹拖进去，秒得域名。
- **Vercel / Cloudflare Pages**：连 Git 仓库 → 构建命令留空 → 发布目录填 `release/web` → 自动分配 HTTPS 域名。

### 3.3 itch.io（游戏社区，免费）

1. 注册 itch.io → `Create new project` → 上传 `release/web` 压缩包或逐文件上传。
2. 嵌入设置选「Web / HTML」，Visibility 设为 Public。
3. 获得页面与 iframe 嵌入码，可嵌入任意网站。

### 3.4 自有服务器（Nginx / Apache）

- 上传 `release/web/` 到服务器 Web 根目录。
- **Nginx** 需为 `.wasm` 配置 MIME：`application/wasm`；若开启线程还需 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp` 响应头。
- 用 Let's Encrypt 申请**免费 HTTPS**（浏览器要求 HTTPS 才能正常跑 WebGL 与音频）。

## 5. 移动端导出（可选）

### Android

1. `编辑器 → 管理导出模板` 内下载 Android 构建模板；安装 Android SDK / 命令行工具（Godot 可一键配置）。
2. `项目 → 导出` 添加 **Android**：填写包名（如 `com.yourname.nailong`）、版本号、密钥库（keystore）。
3. 导出 **APK**（直装测试）或 **AAB**（上 Google Play，需 $25 开发者账号）。

### iOS

1. 需 **macOS + Xcode + Apple 开发者账号（$99/年）**。
2. 导出 **Xcode 工程** → 用 Xcode 签名 → 上架 App Store（审核严格，非商用同人需留意苹果政策）。

## 7. 常见问题（Troubleshooting）

- **黑屏 / 卡加载**：多数因 MIME 或线程（`COOP/COEP`）问题。先按 §2.3 本地 `python -m http.server` 验证；若 OK 则加服务器响应头，或把导出「Threads」关掉。
- **音频不自动播放**：浏览器策略要求首次用户交互后才允许音频；本游戏在点击「开始游戏」后启动音频，符合策略，属正常。
- **存档“丢失”**：Web 下清浏览器缓存 / 换浏览器 / 无痕模式都会丢（IndexedDB 特性），非 bug；移动端本地持久化则稳定。
- **构建体积过大**：压缩贴图、关闭未用特性、或用分离 `.pck` 加载可减小首屏。
- **角色显示为方块/空白**：确认 `assets/characters/0~2.png` 存在且为透明背景 PNG；缺失时游戏会回退到代码绘制圆形。

## 8. 维护与回滚

- 用版本号管理：`project.godot` 的 `config/version` 或导出时的版本字段。
- 保留上一版 Web 产物，出问题时换回旧链接或重新部署即可。
- 角色/数值/题库调整：改 `assets/characters/*.png`、`main.gd` 的 `DIFFS/LEVELS`、`game_manager.gd` 的 `QUESTION_BANK`，重新导出。
